## Topic 1：从外设总线（I2C/SPI）到片上总线的认知映射
* **感知差异的本质**：I2C/SPI 靠软件写寄存器凑协议（时间上串行排队）；片上总线是**纯硬件状态机**，C 语言执行一行指针赋值（如 `*(volatile uint32_t *)0x40001000 = 0x55;` 编译为 `STR/LDR`），CPU 硬件自动在几十根并行铜线上发起时序交互。
* **硬件信号对标（以 APB 为例）**：
  * **并行展开**：将 I2C 串行发送的地址、数据、读写位，展开为独立的 32 位地址线（`PADDR`）和 32 位数据线（`PWDATA/PRDATA`）。
  * **`PSEL`（片选）** $\leftrightarrow$ SPI 的 `CS`（由硬件地址译码器根据目标地址自动拉高）。
  * **`PWRITE`（方向）** $\leftrightarrow$ I2C 的 `R/W` 读写位。
  * **`PREADY`（握手）** $\leftrightarrow$ I2C 的 `ACK`（从设备未就绪时拉低，强行让 CPU 插入等待周期）。

## Topic 2：APB、AHB、AXI 三代片上总线演进与特性对比
| 核心维度 | APB (外围慢速总线) | AHB (中速系统总线) | AXI (高速可扩展主干总线) |
| :--- | :--- | :--- | :--- |
| **设计定位** | 低功耗寄存器配置（接 UART/I2C/GPIO） | MCU 主总线（接片上 SRAM/Flash） | 高性能主干网（接 Cortex-A/DDR/高速 DMA） |
| **双工能力** | **半双工**（读写共用控制逻辑） | **伪全双工**（数据线读写分离，但**共用一套地址线 `HADDR`**，无法同拍发读写地址） | **真全双工**（读写地址、读写数据完全物理分离为 5 个独立通道） |
| **流水线与时序** | **无流水**：一问一答，单次传输固定至少 **2 拍**（Setup $\rightarrow$ Access） | **两级紧耦合流水**：上一笔的数据阶段与下一笔的地址阶段重叠；但地址与数据顺序严格锁死 | **通道彻底异步解耦**：5 个通道独立握手，地址与数据发送无固定拍数绑定 |
| **突发传输 (Burst)** | 不支持 | **伪 Burst**：每传 1 拍数据，地址线都必须重新广播当前拍地址 | **真 Burst**：地址通道**仅发 1 次首地址+长度**，数据通道连续吐完所有数据 |
| **阻塞与并发** | 死等（深度=1） | **一人卡死全线瘫痪**：前序慢外设拉低 `HREADY`，后续快外设请求全部陪等 | **多笔并发（Outstanding）+ 乱序完成（Out-of-Order）**，慢外设不阻塞快外设 |

## Topic 3：AXI 五通道工作机制与核心时序描述
### 1. 五通道物理架构（全单向 + 独立流控）
* **写操作（3 通道）**：写地址（**AW**）$\rightarrow$ 写数据（**W**）$\rightarrow$ 写应答（**B**，从设备回传成功/错误状态）。
* **读操作（2 通道）**：读地址（**AR**）$\rightarrow$ 读数据（**R**，自带读应答状态）。

### 2. 核心握手机制与突发时序（`VALID` / `READY` 法则）
* **双向握手机制**：5 个通道各自独立拥有一对 `xVALID`（源端数据有效）和 `xREADY`（目的端准备接收）。**仅当同一时钟上升沿采样到 `VALID == 1 && READY == 1` 时，完成 1 拍（Beat）传输**。
* **写事务时序流（以 4 拍 Burst 写为例）**：
  1. **AW 阶段**：Master 拉高 `AWVALID`，给出首地址、`AWLEN=3`（4拍）、`AWSIZE`；Slave 拉高 `AWREADY`，**1 拍完成地址交付，AW 通道即刻释放**（甚至可先发 W 数据再发 AW 地址）。
  2. **W 阶段**：Master 连续 4 拍通过 `WDATA` 推数据（每拍均需 `WVALID & WREADY` 同时为 1），第 4 拍必须同步拉高 **`WLAST`** 标志尾拍。
  3. **B 阶段**：Slave 收完尾拍后，在 B 通道拉高 `BVALID` 并返回 `BRESP`（如 `OKAY` 或 `DECERR`），Master 拉高 `BREADY` 接收，整笔写事务闭环。
* **读事务时序流**：Master 在 **AR** 通道握手发 1 次首地址与长度 $\rightarrow$ Slave 准备好后在 **R** 通道连续返回多拍数据，并在最后一拍拉高 **`RLAST`**。

## Topic 4：AXI 被称为“可扩展（eXtensible）”的四大底层支撑
1. **未完成事务并发（Multiple Outstanding）**：因 AR/AW 地址通道与 R/W 数据通道彻底解耦，Master 在第 1 笔请求的数据未返回前，可在地址通道连续发出第 2 ~ $N$ 笔地址，用事务级流水掩盖长物理延迟。
2. **基于 ID 的乱序完成（Out-of-Order）**：每笔事务携带硬件标签（`ARID/RID`、`AWID/BID`）。**同 ID 严格保序，不同 ID 允许乱序返回**（如后发出的片上 SRAM 读数据可超越先发出的慢速外设读数据先行返回 CPU），彻底消除队头阻塞。
3. **协议族裁剪扩展**：同一套握手机制，向上支持 1024-bit 位宽与 256 拍 Burst（**AXI4-Full**）；向下裁剪掉 Burst/ID 变为极简寄存器接口（**AXI4-Lite**）；砍掉地址通道变为纯高速数据流接口（**AXI4-Stream**）。
4. **物理时序扩展（Register Slice）**：由于通道纯单向握手，高频长走线时序不收敛时，可在任意通道中间直接插入寄存器切片（硬件打拍器）切分时序路径，轻松跑上 GHz 主频。

## Topic 5：`DSB` 指令在 AXI 总线上的底层实际工作机制
* **问题根源（Posted Write 提前应答）**：
  CPU 执行外设写指令（如清中断标志 `UART->SR = 0`）时，数据先丢入 CPU 内部 **写缓冲（Store Buffer）**，随后经高速 AXI 发往 **AXI-to-APB 桥**。为了不拖慢 CPU，总线桥收到数据后**直接代替慢速 APB 外设向 CPU 返回 AXI `B` 通道完成应答（`BVALID`）**。CPU 误以为写已落盘，继续执行后续指令（如退出中断），而此时写数据还卡在慢速 APB 桥里排队，导致外设物理状态未更新（引发二次假中断或异步外部中止）。
* **`DSB`（Data Synchronization Barrier）在 AXI 层的硬件动作**：
  1. **冻结流水线**：阻塞 CPU 后续所有指令的执行与内存访问发起。
  2. **排空写缓冲（Drain Store Buffer）**：强制将 CPU 内部 Store Buffer 中积压的所有写请求全部推上 AXI 总线（完成 `AW` 和 `W` 通道握手）。
  3. **等待全局 `B` 通道应答收齐**：CPU 硬件持续监测 AXI **写应答通道（B 通道）** 和 **读数据通道（R 通道）**，必须等到 `DSB` 之前发出的**所有 Outstanding 读写事务全部收到最终的 `BVALID`（写完成）和 `RLAST`（读完成）信号**，才释放 CPU 流水线继续往下执行。
* **工程铁律（`DSB` + 回读）**：
  `DSB` 只能保证写请求收到了 AXI 桥或目标的 `BVALID` 应答；若片上 AXI-to-APB 桥开启了**缓冲提前应答（Buffered Write）**，仅靠 `DSB` 仍无法保证数据已穿过桥写入 APB 末端寄存器。此时必须在写操作后**执行一次对该外设寄存器的读操作（Read-back）** + `DSB`——因为读请求无法提前伪造数据，AXI `R` 通道必须死等前面的写操作穿过 APB 桥落盘后才能返回读数据，从而实现绝对的物理同步。
