简单说：**Wayland 是“通信协议（一套标准/合同）”，合成器（Compositor）是“实现这个协议的程序（真正干活的显示服务器）”**。

  

它们俩的关系，就像 **HTTP 协议** 和 **Nginx / Apache** 的关系：

  

- **Wayland** 规定了“客户端和服务器怎么说话”（比如怎么发显存句柄、怎么通知鼠标点击）。
    
      
    
- **Compositor** 是具体的“后台进程”，负责听这些协议，把各个软件的窗口拼成一张大图，然后塞给内核 DRM 刷到屏幕上。
    
      
    

### 一、 功能、用途与上下文接口

|**维度**|**Wayland（通信协议）**|**Compositor（窗口合成器）**|
|---|---|---|
|**本质**|接口通信规范（Protocol Standard）|运行在用户态的显示服务器（Display Server 进程）|
|**核心用途**|替换古老臃肿的 X11 协议，定义 GUI 应用与显示服务之间的 IPC 接口。|1. 接收所有 App 提交的画面 buffer<br><br>  <br>  <br><br>2. 窗口管理（布局、拖拽、透明度/阴影合成）<br><br>  <br>  <br><br>3. 输入设备分发（鼠标/键盘事件发给哪个窗口）<br><br>  <br>  <br><br>4. 驱动内核 DRM/KMS 屏显|
|**上游接口 (Top)**|**应用层 (Qt / GTK / Electron)**<br><br>  <br>  <br><br>通过 `libwayland-client` 发送 `wl_surface.commit`、`zwp_linux_dmabuf_v1` 等请求。|**Wayland Socket (`/run/user/1000/wayland-0`)**<br><br>  <br>  <br><br>通过 `libwayland-server` 监听并解析 App 传过来的 Unix Socket 字节流与 DMA-BUF `fd`。|
|**下游接口 (Bottom)**|**合成器 (Compositor)**<br><br>  <br>  <br><br>定义了合成器必须支持的事件回调和接口规范。|**内核态 Driver & 硬件**<br><br>  <br>  <br><br>1. 显示：`libdrm` + Mesa GBM $\rightarrow$ `/dev/dri/card0` (DRM/KMS)<br><br>  <br>  <br><br>2. 输入：`libinput` $\rightarrow$ `/dev/input/event*`|

### 二、 在 Linux 生态中具体是由哪些库/软件实现的？

在实际 Linux 系统里，这俩概念落到代码和软件包上，分为三个层次：

  

#### 1. Wayland 官方核心库（协议基础）

这是 Wayland 官方（Freedesktop/Mesa 社区）维护的基础 C 语言库，只负责**解析协议报文与 Socket 序列化**，自己不干任何渲染或画图的事：

  

- **`libwayland-client`**：给 Qt、GTK、Chrome 等客户端 App 用的库，用来向合成器发协议。
    
      
    
- **`libwayland-server`**：给合成器用的库，用来监听 Socket 并接收协议。
    
      
    
- **`wayland-protocols`**：扩展协议集合（包含 `xdg-shell` 窗口控制、`linux-dmabuf` 跨进程零拷贝显存等 XML 定义）。
    
      
    

#### 2. 合成器开发框架 / 基础库（“造合成器的轮子”）

写一个功能完备的合成器需要处理极为复杂的 DRM、EGL、输入设备驱动。为了不重复造轮子，生态里演化出了专门用来开发合成器的基础框架库：

  

- **`wlroots`**：目前 Linux 生态中最火、最强大的模块化合成器 C 语言基础库（由 Sway 团队主导）。它把 DRM 提交、`libinput` 输入处理、 Wayland 协议响应全部封装好了。
    
      
    
- **`libweston`**：Wayland 官方参考实现 Weston 抽离出的合成器核心库。
    
      
    
- **`Smithay`**：Rust 语言生态中用来写 Wayland 合成器的底层库。
    
      
    
- **`Mir`**：Ubuntu（Canonical）早期想替代 X11，后来改造成基于 Wayland 的合成器开发框架。
    
      
    

#### 3. 成品合成器（真正运行在系统里的桌面/服务进程）

这些是最终运行在你的 Linux 系统里、占据 CPU/GPU 进程列表的**真正实体**：

  

- **主营桌面环境自带的合成器**：
    
      
    - **Mutter**：GNOME 桌面环境的核心合成器（GNOME Wayland 模式下的灵魂）。
        
          
        
    - **KWin**：KDE Plasma 桌面环境的核心合成器。
        
          
        
- **基于 `wlroots` 机制开发的独立合成器**：
    
      
    - **Sway**：平铺式（Tiling）窗口合成器（i3wm 的 Wayland 替代品）。
        
          
        
    - **Hyprland**：近年极火的炫酷平铺窗口合成器（支持大量动效、平滑阴影）。
        
          
        
    - **Phoc**：手机/移动端 Linux（如 Purism Librem 5, Phosh 桌面）使用的合成器。
        
          
        
- **官方参考与工业/嵌入式合成器**：
    
      
    - **Weston**：Wayland 官方提供的参考实现（代码极其干净，常用于车载系统、嵌入式 Linux、Rockchip/NXP 官方 SDK 测试）。
