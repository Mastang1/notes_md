## GJB5000A 军用软件研制能力成熟度模型
### 要求的软件开发文档（通常依据 GJB 438 系列）

在军工嵌入式开发中，全生命周期要求的文档通常分为以下几大类：
1. **计划与管理类文档**：

    - **软件研制计划**（整体进度、资源、风险管理）

    - **软件配置管理计划**（SCMP）

    - **软件质量保证计划**（SQAP）

    - **软件测试计划**（STP）

2. **需求与设计类文档**：

    - **软件需求规格说明（SRS）**：明确系统要实现的功能、性能、接口等。

    - **软件顶层设计说明（SSDD） / 系统设计说明**：软件整体架构、模块划分、多任务调度策略等。

    - **软件底层设计说明（SDD） / 模块设计说明**：详细到函数、数据结构、状态机设计。

    - **接口设计说明（IDD）**：内部总线、驱动、与其他设备通信协议的接口定义。

3. **测试类文档**：

    - **软件测试说明（STS）**：测试用例、测试步骤、预期结果。

    - **软件测试报告（STR）**：测试执行结果、缺陷统计与分析。

4. **用户与总结类文档**：

    - **软件用户手册（SUM）**

    - **软件研制总结报告**

### 三、 需要哪些测试？（基于 GJB 5000A 的“验证”与“确认”过程域）

在 GJB 5000A 的工程过程域中，测试被严格划分为验证（Verification）**和**确认（Validation）两大体系：

  

#### 1. 验证（Verification —— “保证把软件做对”）

侧重于检查中间产品是否满足阶段性技术规范：

  

- **静态测试**：

    - **静态代码分析**：使用工具（如 Coverity、Klocwork、PC-lint 等）进行自动化扫描，检查是否符合编码标准（如 MISRA C/C++）以及是否存在内存泄漏、越界、空指针。

    - **同行评审（Peer Review / Code Review）**：对需求、设计、代码进行多人的交叉检查和评审。

- **动态测试**：

    - **单元测试（Unit Testing）**：对嵌入式应用的各个底层函数、模块进行白盒测试，通常要求达到较高的代码覆盖率（如语句覆盖、判定覆盖、MC/DC覆盖）。

    - **集成测试（Integration Testing）**：验证多个模块、驱动与应用层、或多任务（RTOS）之间的接口与协同。

## ASPICE
### 一、 一句话对标关系
- **GJB 5000A 差不多等同于车规级的 ASPICE**（两者本质上都是基于 CMMI 模型的**研发过程成熟度标准**）。
- 如果考虑**代码安全与防错要求（如前面聊到的等级划分）**，它还对应车规级的 **ISO 26262（汽车功能安全标准，ASIL A/B/C/D 分级）**。
### 二、 详细对比：GJB 5000A vs ASPICE & ISO 26262

|**维度**|**军工/航天领域 (GJB 体系)**|**汽车电子/车规级 (Automotive)**|**两者核心异同点**|
|---|---|---|---|
|**过程成熟度管理**|**GJB 5000A** (军用软件能力成熟度)|**ASPICE** (汽车软件过程改进及能力测定)|**几乎一模一样**。都源于 CMMI 模型，强调双向可追溯性（需求-设计-代码-测试）、V模型研发流程、同行评审（Code Review）、配置管理和严格变更。|
|**功能安全与失效分级**|**关键级 / 重要级 / 一般级** (I/II/III 级)|**ISO 26262** (ASIL A / B / C / D)|理念完全一致。ASIL D（最高安全等级）对标军工关键级（I级）：**严禁动态内存**、严格控制圈复杂度、测试要求达到 **MC/DC 覆盖率**。|
|**编码规范标准**|**GJB 5369** / 军工 C 语言规范|**MISRA C/C++** / **AUTOSAR C++14**|规则高度相通。实际上军工很多编码规范就是参考 MISRA 制定或裁剪的。|
|**文档与交付物**|**GJB 438B/C** (SRS, SSDD, SDD, STS...)|**ASPICE 工作产品** (SYS.2, SWE.1, SWE.3, SWE.6...)|叫法不同但内容对应。都要求从系统需求到软件架构、详细设计、单元测试规格说明书一应俱全。|

### 三、 面试时的高分打比方（话术指南）
如果在面试汽车电子、新能源车企（如蔚小理、比亚迪、华为车BU、Tier 1 供应商等）时，面试官问你“做过 ASPICE 吗”或者“了解车规软件规范吗”，你可以这样顺畅地迁移你的知识：
> “**了解的。车规级的 ASPICE 和 ISO 26262，在底层逻辑上跟我之前了解和接触的 GJB 5000A 以及军工功能安全规范是高度一致的。**
> - **在过程管理上**：GJB 5000A 和 ASPICE 都是基于 CMMI 的 V 模型体系。它们都极其看重**双向可追溯性**——从软件需求（SYS/SWE）一直追溯到架构设计、详细设计、代码以及单元和集成测试用例，同时对配置管理（Git/Jira）和同行评审（Code Review）有着几乎相同的硬性要求。
> - **在安全性分级上**：车规级的 **ASIL D** 等级要求，对应军工的**一级（关键级）软件**。比如在编码时严禁使用 `malloc` 等动态内存、必须遵循 MISRA C 规范、限制函数圈复杂度，以及在单元测试中必须达到 **MC/DC 级的结构覆盖率**。
> 所以虽然行业不同、文档表格的格式名称略有差异，但我已经养成了这种高可靠性、规范化的嵌入式软件开发习惯，能非常快速地适应车规级 ASPICE 和 ISO 26262 的研发要求。”
