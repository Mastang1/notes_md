# IP 分片（IP Fragmentation）理由笔记

## 1. 核心原因：沿途链路 MTU 不一致
* 不同链路介质或隧道封装的最大传输单元（MTU）可能不同（常见以太网为 `1500` 字节，部分隧道/蜂窝/PPP 链路更小）。
* 发送端传输层发包时无法预先掌握整条跨网路径每一跳的 MTU，因此网络层（IP）需要在满足 MTU 约束时对超长分组切分（IPv4 路径中源端和出接口 MTU 较小的路由器均可分片；IPv6 中间路由器不分片，仅源端可分片并依赖 PMTU 发现）。

## 2. 分层职责与复用：集中放进 IP 层而非上层或链路层
* **不交给上层（TCP/UDP/应用）全权处理**：UDP 等协议无连接、无 MSS/重传状态，且应用/传输层不应感知底层链路 MTU 细节；TCP 的 MSS 虽可提前分段减少分片，但仍需网络层规则兜底。
* **不交给具体链路层各自实现**：避免以太网、Wi-Fi、PPP 等不同链路层重复实现分片与重组，同时屏蔽底层链路差异。

## 3. 组包位置与工程代价
* **只在目的主机重组**：中间路由器只转发分片，不拼包；目的主机按 `Identification` 归类、按 `Fragment Offset` 和 `MF` 标志位还原（不是按到达先后盲拼）。
* **工程代价**：丢任意一片会导致整组重组失败、整包丢失；路由器分片与重组会增加 CPU/内存开销，因此高性能通信通常尽量控制单包在 MTU 以内，避免 IP 分片。
* **对比工业/实时总线（如 EtherCAT）**：若不需要跨网段 IP 路由与动态大包传输，常直接基于链路帧承载数据，省去 IP 层及分片重组带来的开销与抖动。
