## 模型 21：断电安全提交记录

**优先级：P1｜层次：Storage / Library / User App**

### 第一性原理

Flash 写入不是原子的，写到任意字节时都可能掉电；Flash 通常还只能把位从 1 写成 0，擦除则以大扇区进行。原地覆盖唯一副本无法区分“新值完整”与“只写了一半”。

从约束推出 append/双槽提交协议：

1. 保留旧的已提交记录；
2. 在新位置写 payload；
3. 写 version/length/CRC 等 metadata；
4. 最后写一个很小的 commit marker；
5. 启动时只选择 marker、CRC 都有效且序号最新的记录；
6. 空间回收前确保至少一个有效副本仍存在。

提交标记写在最后，是把多步物理写压缩成一个可判定的逻辑提交点。

### 费曼解释

写合同不能边擦旧合同边写新合同。先在新纸上完整写好、核对页码和校验章，最后签字生效；签字前掉电，仍用旧合同。签字后的新合同校验失败，也退回旧合同。

### 核心不变量

- 任意复位点至少有一个完整已提交版本；
- payload 先于 metadata/commit；
- CRC 覆盖所有决定语义的数据和版本信息；
- sequence 比较处理回绕；
- 擦除/垃圾回收不能先摧毁最后有效副本；
- 写后读回验证与设备错误要进入错误路径。

### 核心场景

~~~mermaid
sequenceDiagram
    participant A as "Application"
    participant F as "Flash/NVS"
    participant B as "Boot Loader"
    A->>F: append payload(seq=11)
    A->>F: write metadata + CRC
    Note over A,F: 此时掉电，记录仍未提交
    A->>F: write COMMIT last
    B->>F: scan records
    F-->>B: seq=10 valid, seq=11 valid
    B->>B: choose newest seq=11
~~~

### 最小 Demo（C11，RAM 模拟双槽 Flash）

~~~c
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>
#include <string.h>

#define COMMITTED 0xA55Au
typedef struct {
    uint32_t seq;
    uint32_t value;
    uint32_t crc;
    uint16_t commit;
} record_t;

static record_t slots[2];

static uint32_t checksum(uint32_t seq, uint32_t value) {
    return 0x9E3779B9u ^ seq ^ (value * 2654435761u);
}

static bool valid(const record_t *r) {
    return r->commit == COMMITTED &&
           r->crc == checksum(r->seq, r->value);
}

static void save(unsigned slot, uint32_t seq, uint32_t value,
                 bool simulate_power_loss) {
    record_t *r = &slots[slot];
    r->commit = 0u;
    r->seq = seq;
    r->value = value;
    r->crc = checksum(seq, value);
    if (!simulate_power_loss) r->commit = COMMITTED; /* 最后一步 */
}

static const record_t *load_latest(void) {
    const record_t *best = NULL;
    for (unsigned i = 0; i < 2u; ++i) {
        if (valid(&slots[i]) && (best == NULL || slots[i].seq > best->seq)) {
            best = &slots[i];
        }
    }
    return best;
}

int main(void) {
    save(0u, 1u, 100u, false);
    save(1u, 2u, 200u, true); /* 模拟 commit 前掉电 */
    const record_t *r = load_latest();
    printf("seq=%u value=%u\n", r->seq, r->value);
}
~~~

### 工程边界与误用

- 示例 checksum 不是生产 CRC；安全数据还需要认证/MAC；
- 不能假设一个 C 结构体能直接稳定落盘，要定义字节序、对齐和 schema version；
- Flash 最小写粒度可能不允许单独改 commit 字段；
- 真实 sequence 回绕比较可用有符号差或更大代数；
- 磨损均衡、扇区坏块和垃圾回收是协议的一部分；
- 测试必须在每个写步骤后模拟掉电并重启扫描。

## 模型 22：A/B 候选 + 确认/回滚

**优先级：P1｜层次：Boot / Storage / User App**

### 第一性原理

校验通过只能证明镜像完整且来自可信源，不能证明它在真实硬件上能启动、喂狗、联网或兼容现有数据。若第一次启动就永久替换旧版本，一个逻辑 bug 会使设备变砖。

因此把“安装成功”拆成两个阶段：

1. 候选版本进入 trial 状态；
2. 启动候选并运行最小健康检查；
3. 应用显式 confirm 后才永久生效；
4. 未确认即复位/超时，bootloader 回滚到已确认版本。

它本质上是跨复位的两阶段提交：bootloader 提供 prepare/trial，应用提供 commit/confirm。

### 费曼解释

新飞行员不会第一天就烧掉旧航线手册。先试飞，确认能起飞、导航和降落后才签字转正；试飞中出问题，下次仍由老飞行员接管。

### 核心不变量

- 始终保留一个可验证、已确认的恢复版本；
- trial 状态必须持久化并能识别意外复位；
- confirm 只在真实健康条件满足后发生；
- 新旧版本的数据 schema 要向前/向后兼容或可回滚迁移；
- 防回滚安全计数与“可靠性回滚”是不同策略，需要一起设计；
- 更新流程必须幂等，重复下载/复位不会破坏可启动版本。

### 核心场景

~~~mermaid
sequenceDiagram
    participant U as "Updater"
    participant B as "Bootloader"
    participant N as "New App"
    participant O as "Old Confirmed Slot"
    U->>B: install candidate in slot B
    B->>B: verify + mark TEST
    B->>N: boot candidate
    alt 自检、关键任务和通信均健康
        N->>B: confirm image
        Note over B,N: 下次继续启动新版本
    else 崩溃/看门狗/未确认复位
        B->>O: revert and boot old image
    end
~~~

### 最小 Demo（C11，模拟启动决策）

~~~c
#include <stdbool.h>
#include <stdio.h>

typedef enum { SLOT_EMPTY, SLOT_CONFIRMED, SLOT_TRIAL } slot_state_t;
typedef struct { unsigned version; slot_state_t state; bool valid; } slot_t;

static unsigned choose_boot(const slot_t slots[2]) {
    for (unsigned i = 0; i < 2u; ++i) {
        if (slots[i].valid && slots[i].state == SLOT_TRIAL) return i;
    }
    if (slots[1].valid && slots[1].state == SLOT_CONFIRMED) return 1u;
    return 0u;
}

static void on_unconfirmed_reset(slot_t slots[2], unsigned trial) {
    if (slots[trial].state == SLOT_TRIAL) {
        slots[trial].state = SLOT_EMPTY;
        slots[trial].valid = false;
    }
}

int main(void) {
    slot_t slots[2] = {
        { 1u, SLOT_CONFIRMED, true },
        { 2u, SLOT_TRIAL, true }
    };
    unsigned boot = choose_boot(slots);
    printf("first boot slot=%u\n", boot);
    on_unconfirmed_reset(slots, boot);
    printf("after failed trial slot=%u\n", choose_boot(slots));
}
~~~

### 确认门槛

候选版本至少应证明：

- 主循环和关键任务经过多个心跳周期；
- 必要存储可读写且 schema 迁移完成；
- 看门狗、时钟、关键驱动已初始化；
- 核心通信链路或产品关键功能达到可接受状态；
- 复位原因不是候选版本反复崩溃。

不要在进入 main 后立即确认；那只证明跳转成功。

### 工程边界与误用

- A/B 需要额外 Flash；空间不足时交换算法更复杂；
- 应用回滚但配置已做不可逆迁移，仍可能无法恢复；
- 频繁自动回滚会掩盖现场故障，应保存失败版本和原因；
- 安全防降级可能禁止回到有漏洞的旧版本，需要工厂恢复策略；
- Bootloader 本身的升级需要更强的不可砖设计。
