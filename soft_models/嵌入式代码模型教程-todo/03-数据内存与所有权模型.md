## 模型 9：环形缓冲

**优先级：P0｜层次：HAL / Driver / Library**

> [!note] 与已有 SPSC 笔记的关系
> SPSC 是“谁能并发修改 head/tail”的并发模型；环形缓冲是“如何让固定数组循环复用”的存储模型。本节聚焦容量语义、发布顺序与满策略，不重复完整的无锁证明。

### 第一性原理

连续流到达时，如果每消费一个元素就搬移剩余数据，时间复杂度和总线流量都浪费。固定数组加两个单调前进的游标即可把“搬数据”变成“移动索引”。

关键歧义是 head 等于 tail 既可能表示空也可能表示满。最小解决方案是浪费一个槽，令：

- 空：head == tail；
- 满：next(head) == tail；
- 可用容量：N - 1。

### 费曼解释

像环形跑道上的取餐窗口：厨师把餐放到下一个空格，顾客从自己的下一个格取走。盘子不搬家，只移动两个指示牌。故意留一个空格，就能一眼区分“全空”和“追尾”。

### 核心不变量

- 生产者先写元素，再发布 head；
- 消费者先读元素，再发布 tail；
- 单调游标只由各自角色修改；
- 容量、满策略和并发假设属于 API 契约；
- 多生产者或多消费者不能直接套用 SPSC。

### 核心场景

~~~mermaid
sequenceDiagram
    participant P as "Producer/ISR"
    participant B as "Ring Buffer"
    participant C as "Consumer/Task"
    P->>B: write buf[head]
    P->>B: publish head
    C->>B: observe head
    C->>B: read buf[tail]
    C->>B: publish tail
~~~

### 最小 Demo（C11，单上下文逻辑骨架）

~~~c
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>

#define N 8u
typedef struct {
    uint8_t data[N];
    unsigned head;
    unsigned tail;
} ring_t;

static unsigned next(unsigned i) { return (i + 1u) % N; }

static bool push(ring_t *r, uint8_t value) {
    unsigned n = next(r->head);
    if (n == r->tail) return false;
    r->data[r->head] = value;
    r->head = n;
    return true;
}

static bool pop(ring_t *r, uint8_t *value) {
    if (r->tail == r->head) return false;
    *value = r->data[r->tail];
    r->tail = next(r->tail);
    return true;
}

int main(void) {
    ring_t r = {0};
    uint8_t value;
    push(&r, 42u);
    pop(&r, &value);
    printf("%u\n", value);
}
~~~

### 工程边界

- ISR/线程 SPSC 需要平台内存模型、原子性和 acquire/release 语义审查；
- DMA 会绕过 CPU cache，一致性还需 cache clean/invalidate 和内存屏障；
- 帧协议还需长度、分隔符或 BipBuffer，不要假设一帧永不跨数组末尾；
- 覆盖旧数据适合“最新值”，不适合控制命令。

## 模型 10：固定大小对象池

**优先级：P0｜层次：OS / Library**

### 第一性原理

通用堆要处理任意大小和生命周期，因此会带来元数据、不可预测查找时间和外部碎片。若对象最大数量 K 与固定大小 S 在设计期已知，预留 K 个块并维护空闲链表即可：

- 分配和释放 O(1)；
- 内存上界 K × S 可证明；
- 没有外部碎片；
- 资源耗尽成为可测试的正常分支。

### 费曼解释

停车场不是每来一辆车就临时买一块地；它预先画好 K 个一样的车位。满了就明确告诉入口“没有车位”，离场后车位立刻复用。

### 核心场景

~~~mermaid
sequenceDiagram
    participant A as "Allocator Client"
    participant P as "Fixed Pool"
    participant C as "Consumer"
    A->>P: alloc()
    P-->>A: block
    A->>C: handoff(block)
    C->>P: free(block)
    Note over P: block 回到 free list
~~~

### 最小 Demo（C11）

~~~c
#include <stddef.h>
#include <stdio.h>

#define BLOCKS 4
#define PAYLOAD 32

typedef union block {
    union block *next;
    unsigned char bytes[PAYLOAD];
} block_t;

static block_t storage[BLOCKS];
static block_t *free_list;

static void pool_init(void) {
    free_list = NULL;
    for (size_t i = 0; i < BLOCKS; ++i) {
        storage[i].next = free_list;
        free_list = &storage[i];
    }
}

static void *pool_alloc(void) {
    if (free_list == NULL) return NULL;
    block_t *b = free_list;
    free_list = b->next;
    return b->bytes;
}

static void pool_free(void *p) {
    if (p == NULL) return;
    block_t *b = (block_t *)p;
    b->next = free_list;
    free_list = b;
}

int main(void) {
    pool_init();
    void *p = pool_alloc();
    printf("allocated=%s\n", p ? "yes" : "no");
    pool_free(p);
}
~~~

### 工程边界与误用

- 不同尺寸对象应分多个 size class，避免内部浪费；
- 并发访问需要短临界区、锁或专用 owner；
- 必须检测 double free、越界指针和泄漏；
- ISR 分配需保证实现真正无阻塞且中断安全；
- 池满时不能偷偷回退到堆，否则实时上界失效。

## 模型 11：零拷贝所有权 + 引用计数

**优先级：P1｜层次：Driver / Network Stack / Library**

### 第一性原理

异步发送返回时，硬件可能尚未读取缓冲。若调用者立即复用它，就会发生 use-after-reuse；若每层都复制，吞吐和功耗变差。

零拷贝的核心不是“没有 memcpy”，而是明确缓冲生命周期：

1. 创建者拥有一个引用；
2. 每个异步持有者增加引用；
3. 每个持有者完成后释放；
4. 引用降为零时才回到池；
5. 持有共享引用期间数据不可变，或使用 copy-on-write。

### 费曼解释

图书馆的一本书被三个人借阅时，不能因为第一个人还书就销毁。计数器记录还有多少借阅者；最后一个归还后，书才回到书架。零拷贝节省的是复印，代价是必须认真管借阅关系。

### 核心场景

~~~mermaid
sequenceDiagram
    participant A as "Application"
    participant B as "Buffer"
    participant S as "Protocol Stack"
    participant D as "DMA Driver"
    A->>B: ref=1, fill immutable payload
    A->>S: submit(B)
    S->>B: retain() ref=2
    S->>D: tx(B)
    D->>B: retain() ref=3
    A->>B: release() ref=2
    D->>B: release() ref=1
    S->>B: release() ref=0 -> pool
~~~

### 最小 Demo（C11）

~~~c
#include <assert.h>
#include <stdatomic.h>
#include <stdio.h>

typedef struct {
    atomic_uint refs;
    unsigned char payload[64];
} buffer_t;

static void recycle(buffer_t *b) {
    (void)b;
    puts("recycled");
}

static void retain(buffer_t *b) {
    unsigned old = atomic_fetch_add_explicit(&b->refs, 1u,
                                              memory_order_relaxed);
    assert(old > 0u);
}

static void release(buffer_t *b) {
    unsigned old = atomic_fetch_sub_explicit(&b->refs, 1u,
                                              memory_order_acq_rel);
    assert(old > 0u);
    if (old == 1u) recycle(b);
}

int main(void) {
    buffer_t b = { .refs = 1u };
    retain(&b);
    release(&b);
    release(&b);
}
~~~

### 工程边界与误用

- 引用计数不能解决循环引用；
- DMA cache 一致性、对齐和可访问地址仍需平台处理；
- 计数位宽要防溢出，释放路径必须唯一且可审计；
- 若所有权可以单向移动，优先用 move/handoff，比引用计数简单；
- 不可变约束必须进入 API 文档。

## 模型 12：Ping-Pong 双缓冲

**优先级：P1｜层次：HAL / Driver / DSP**

### 第一性原理

采集和处理都需要独占同一块可变内存时会互相等待。准备两个等价缓冲 A/B，让 DMA 填 A 时 CPU 处理 B，事务完成时交换角色，即可把两段串行时间重叠。

稳定吞吐的必要条件仍是：

\[
T_{process} < T_{fill}
\]

若处理长期更慢，双缓冲只把溢出推迟一帧。

### 费曼解释

食堂有两个托盘：厨师装满一个就交给服务员，同时开始装另一个。只有一个托盘时，两人必须轮流等；两个托盘能并行，但服务员如果一直比厨师慢，最终仍会堵住。

### 核心场景

~~~mermaid
sequenceDiagram
    participant DMA as "DMA"
    participant ISR as "完成 ISR"
    participant CPU as "Processor"
    DMA->>DMA: fill A
    DMA->>ISR: A complete
    ISR->>DMA: switch to B
    ISR->>CPU: post(A_READY)
    par 并行
        DMA->>DMA: fill B
    and
        CPU->>CPU: process A
    end
~~~

### 最小 Demo（C11，模拟角色交换）

~~~c
#include <stddef.h>
#include <stdio.h>

#define SAMPLES 8
static unsigned short buf[2][SAMPLES];
static unsigned dma_active;
static unsigned ready = 2u;

static void dma_complete_isr(void) {
    ready = dma_active;
    dma_active ^= 1u;
    /* program_dma_destination(buf[dma_active]); */
}

static void process_ready(void) {
    if (ready > 1u) return;
    unsigned long sum = 0u;
    for (size_t i = 0; i < SAMPLES; ++i) sum += buf[ready][i];
    printf("buffer %u sum=%lu\n", ready, sum);
    ready = 2u;
}

int main(void) {
    for (size_t i = 0; i < SAMPLES; ++i) buf[0][i] = (unsigned short)i;
    dma_complete_isr();
    process_ready();
}
~~~

### 工程边界与误用

- 必须明确哪个缓冲由 DMA 拥有，CPU 不得同时写；
- 若可能连续完成两帧，单个 ready 标志会覆盖事件，应改为描述符队列；
- 注意 cache clean/invalidate、内存对齐与 DMA 可达内存；
- 半传输/全传输中断的单环缓冲是同一思想的变体；
- 处理超时要统计 overrun 并定义丢帧或降采样策略。

## 模型 13：读多写少一致快照

**优先级：P2｜层次：HAL / OS / Telemetry**

### 第一性原理

读取多个相关字段时，单独的原子读不能保证它们来自同一次更新。例如先读经度、写者更新、再读纬度，会得到不存在的组合。

在“单写者、写操作很短、读者不能阻塞”的约束下，可用序列计数：

1. 写前把版本改成奇数；
2. 写完把版本改成下一个偶数；
3. 读者先读版本，再复制数据，再读版本；
4. 版本相同且为偶数才接受，否则重试。

### 费曼解释

抄黑板时先看老师是否正在写。抄完再看一次黑板右上角的页码；若页码没变且老师没在写，这份抄录就是同一版，否则重抄。

### 核心场景

~~~mermaid
sequenceDiagram
    participant R as "Reader"
    participant S as "Sequence"
    participant W as "Single Writer"
    R->>S: read seq=10
    W->>S: seq=11（写入中）
    W->>W: update x,y
    W->>S: seq=12（完成）
    R->>S: read seq=12
    Note over R: 10 != 12，丢弃并重读
~~~

### 最小 Demo（C11）

~~~c
#include <stdatomic.h>
#include <stdio.h>

typedef struct { atomic_int x; atomic_int y; } shared_point_t;
typedef struct { int x; int y; } point_t;
static shared_point_t shared;
static atomic_uint sequence;

static void write_point(int x, int y) {
    atomic_fetch_add_explicit(&sequence, 1u, memory_order_relaxed);
    atomic_thread_fence(memory_order_release);
    atomic_store_explicit(&shared.x, x, memory_order_relaxed);
    atomic_store_explicit(&shared.y, y, memory_order_relaxed);
    atomic_fetch_add_explicit(&sequence, 1u, memory_order_release);
}

static point_t read_point(void) {
    point_t copy;
    unsigned begin, end;
    do {
        begin = atomic_load_explicit(&sequence, memory_order_acquire);
        if (begin & 1u) continue;
        copy.x = atomic_load_explicit(&shared.x, memory_order_relaxed);
        copy.y = atomic_load_explicit(&shared.y, memory_order_relaxed);
        atomic_thread_fence(memory_order_acquire);
        end = atomic_load_explicit(&sequence, memory_order_relaxed);
    } while (begin != end || (end & 1u));
    return copy;
}

int main(void) {
    write_point(10, 20);
    point_t p = read_point();
    printf("%d,%d\n", p.x, p.y);
}
~~~

### 何时不用

- 多写者未被外部锁串行化；
- 写者可能被读者无限期阻塞或写临界段很长；
- 数据含指针且指向对象可能在读时释放；
- 硬实时读者不能容忍重试；
- 语言内存模型下对非原子对象并发访问构成数据竞争时，需要平台原语或改用双缓冲快照。
